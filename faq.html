Perguntas Frequentes

Respostas às dúvidas mais comuns sobre acessibilidade

Sobre o Plugin

P: O plugin é gratuito?

R: Sim! O A11y Avaliator é 100% gratuito e pode ser usado ilimitadamente.

P: Preciso ter conhecimento técnico para usar?

R: Não! É feito para iniciantes. Você clica e vê os problemas. Mas conhecimento ajuda a entender as soluções.

P: Funciona em quais navegadores?

R: Chrome, Edge, Brave (Chromium). Firefox em desenvolvimento. Safari com App Store.

P: O plugin coleta meus dados?

R: Não! Tudo é análise local. Seus dados nunca deixam seu navegador. Sem rastreamento.

P: Quanto tempo leva uma análise?

R: WCAG + Contraste: 5-15 segundos. Com Teclado + Leitor: 30-60 segundos. Depende do tamanho da página.

Sobre Acessibilidade

P: É obrigatório fazer sites acessíveis?

R: Depende do país/indústria. Na EU, Brasil, EUA é obrigatório para setor público. Setor privado: melhor respeitar WCAG AA. Clientes cada vez mais exigem.

P: Qual é o nível recomendado de acessibilidade?

R: WCAG AA é o padrão recomendado para a maioria. Equilibra acessibilidade com esforço de implementação. AAA é "nice to have".

P: Acessibilidade é caro?

R: Não necessariamente. 80% dos problemas são rápidos de corrigir. Custa mais ignorar e ter problemas legais depois.

P: Acessibilidade melhora SEO?

R: Indiretamente. Alt text em imagens, headings corretos, etc. ajudam. Mas não é a razão principal para fazer.

P: Acessibilidade prejudica o design?

R: Não! Bom design é inclusivo por default. Contraste melhor, espaçamento melhor, etc. = melhor para todos.

Sobre Testes

P: Por que o plugin não encontra 100% dos problemas?

R: Testes automáticos encontram ~50-70%. Experiência real requer teste manual com usuários de verdade.

P: Qual teste devo começar?

R: WCAG + Contraste. São rápidos, cobrem maioria dos problemas. Depois adicione Teclado + Leitor.

P: Como testar sem instalar leitor de tela?

R: Use plugin como este, ferramentas online, ou contrate testers com deficiência para feedback real.

P: Todos os relatórios de erro do plugin são verdade?

R: 90% sim. Pode haver falsos positivos. Se dúvida, teste manualmente ou com outro plugin.

P: Posso confiar 100% no score do plugin?

R: Não. É bom indicador, mas não substitui teste manual. Use como guia de progresso.

Sobre Correções

P: Por onde começo a corrigir?

R: Pelos problemas Critical da lista. Impactam mais o score e a experiência real.

P: Tenho que corrigir todos os problemas?

R: Idealmente sim, mas priorize. Mire em WCAG AA (~80% score). AAA é "nice to have".

P: Quanto tempo leva corrigir um site?

R: Pequeno site (10 páginas): 10-20 horas. Grande site: semanas/meses. Depende do estado atual.

P: Devo corrigir tudo de uma vez?

R: Não. Incremental é melhor. Uma seção por vez, teste, valide. Menos bugs assim.

P: Como garantir que correção está certa?

R: Rode plugin novamente. Score deve melhorar. Depois teste com teclado + leitor manualmente.

Sobre Ferramentas

P: Qual leitor de tela devo usar?

R: NVDA se usa Windows (gratuito). VoiceOver se Mac (integrado). Ambos são bons para começar.

P: Que más práticas com leitores de tela?

R: Usar DIV para tudo, sem ARIA, sem headings, links genéricos. Tudo quebra a navegação.

P: Posso usar A11y Avaliator + Axe juntos?

R: Sim! Complementam. Axe é mais detalhe. Este plugin é mais user-friendly.

P: Como medir progresso ao longo do tempo?

R: Rode análise mensal. Anote score no spreadsheet. Veja tendência subindo (ou não!).

Sobre Negócio

P: Existe ROI em acessibilidade?

R: Sim! Usuários com deficiência = ~1 bilhão no mundo. Acessibilidade = mais usuários, melhor UX para todos.

P: Como convencer meu chefe?

R: Mostre: Compliance legal, risco de processo, feedback de usuários, melhoria de SEO, image/reputação.

P: Qual é o custo de não fazer acessibilidade?

R: Processos judiciais (podem custar milhões), usuários perdidos, reputação. Melhor prevenir.

P: Como integrar a11y no processo de desenvolvimento?

R: Adicione teste de acessibilidade à checklist de deploy. Use plugin durante desenvolvimento. Educa times.
