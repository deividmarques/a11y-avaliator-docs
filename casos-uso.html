🎯 Casos de Uso

Como diferentes perfis usam o A11y Avaliator

Cenário 1: Desenvolvedor Frontend

👨‍💻 João é um desenvolvedor frontend

Situação: Trabalha em e-commerce, precisa melhorar acessibilidade

Processo:

  1. Instala o plugin no Chrome
  2. Abre site em desenvolvimento
  3. Clica no plugin, executa análise WCAG + Contraste
  4. Vê score inicial: 52% 🔴 Crítico
  5. Vê lista de problemas: 15 Critical, 8 Serious
  6. Abre guia de correções, começa a corrigir
  7. Implementa alt text, escurece cores, adiciona labels
  8. Roda plugin novamente: 78% ✅ Bom!
  9. Combina com teste manual de teclado, valida
  10. Entra em produção com confiança

Benefício: Feedback rápido durante desenvolvimento. Economiza tempo de correção posterior

Cenário 2: Auditor de Acessibilidade

📊 Maria é consultora de acessibilidade

Situação: Audita 20+ sites por mês para clientes

Processo:

  1. Recebe lista de URLs do cliente
  2. Para cada URL, abre o plugin e executa análise completa
  3. Anota score e problemas principais
  4. Usa leitor de tela (NVDA) para testes manuais profundos
  5. Cria relatório combinando dados do plugin + manual
  6. Apresenta ao cliente com recomendações priorizadas
  7. 6 meses depois, roda plugin novamente para validar progresso

Benefício: Plugin acelera análise inicial. Deixa Maria focar em testes mais complexos que ferramentas não cobrem

Cenário 3: QA Testing

🧪 Pedro é QA de um banco

Situação: Precisa garantir acessibilidade antes de release

Processo:

  1. Adiciona teste de acessibilidade à checklist QA
  2. Antes de aprovar build, roda plugin
  3. Se score < 80%, rejeita e marca como blocker
  4. Desenvolvedores recebem feedback imediato
  5. Iteração rápida: fix → teste → release
  6. Cada release tem acessibilidade garantida

Benefício: Acessibilidade não fica para depois. Integrado ao workflow de qualidade

Cenário 4: Designer Aprendendo Acessibilidade

🎨 Ana é designer mas quer aprender a11y

Situação: Nunca trabalhou com acessibilidade, precisa aprender

Processo:

  1. Lê introdução ao acessibilidade
  2. Lê seção de contraste
  3. Instala verificador de contraste online
  4. Testa designs antigos, aprende o que está errado
  5. Começa a verificar contraste antes de entregar designs
  6. Simula daltonismo no Figma com plugin
  7. Sobe bar de qualidade de acessibilidade nos designs

Benefício: Docs educacionais + ferramenta prática = learning by doing

Cenário 5: Product Manager Rastreando Progresso

📈 Carlos é PM de SaaS

Situação: Quer rastrear progresso de acessibilidade como métrica

Processo:

  1. Todo mês, roda plugin no app principal
  2. Anota score em spreadsheet
  3. Junho: 45%. Julho: 58%. Agosto: 72%
  4. Mostra gráfico para CEO/board: "Acessibilidade melhorando"
  5. Prioriza sprint de acessibilidade baseado em score
  6. Anuncia para usuários: "Agora 80% acessível!"

Benefício: Métrica tangível de progresso. Justifica investimento em acessibilidade

Cenário 6: Startup Bootstrapped

🚀 Uma dupla de founders

Situação: Startup com orçamento zero para consultores caros

Processo:

  1. Quer ser inclusivos mas não podem pagar auditoria
  2. Descobrem A11y Avaliator (gratuito!)
  3. Usam plugin + documentação para aprender
  4. Conseguem score de 75% com trabalho próprio
  5. Economizam $5k em consulta profissional
  6. Ainda ganham no marketing: "Acessível desde dia 1"

Benefício: Democratiza acessibilidade. Não precisa ser rico para incluir

Cenário 7: Empresa Grande Com Process

🏢 Time de 50+ devs em grande corp

Situação: Precisa padronizar acessibilidade em 200+ páginas

Processo:

  1. Define WCAG AA como padrão corporativo
  2. Treina todos devs no plugin + guia
  3. Adiciona CI/CD check: score deve ser >= 80%
  4. Cada PR roda plugin automaticamente
  5. Se falhar, developer recebe feedback
  6. Força qualidade consistente em toda base
  7. Score cai se alguém quebra acessibilidade

Benefício: Acessibilidade como parte da cultura de qualidade, não afterthought
